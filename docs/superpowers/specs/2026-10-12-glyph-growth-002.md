# Glyph Growth 002 — typed expansion from a particular

Status: experimental sidecar under 3rdi, following Glyph Transition 001.

## Why

Glyph Transition 001 proved two distinct movements: `Y → ·` is a lossy quotient; `L → U` preserves simple-path topology. The owner then supplied the **generative counterparts**:

```text
· < Y
· < l < L < U
```

The glyphs are *creative labels* for graph specimens. A left-pointing `<` means "can be extended under a declared rule," not subsethood, order of meaning, proof of history, or recoverability from a collapsed dot.

## Small executable grammar

| Glyph movement | Operator | Growth invariant | Addition |
|---|---|---|---|
| `· < l` | `EXTEND` | Retain the origin | One vertex + one edge |
| `l < L` | `BEND` | Preserve original line and path connectivity | One vertex + one edge; right angle |
| `L < U` | `RETURN` | Preserve the two original edges, simple path and two endpoints | One vertex + one edge; open U with antiparallel outer uprights |
| `· < Y` | `FORK` | Retain origin as a degree-three junction | Three leaves + three edges |

In this initial right-angle model, `BEND` means **turn-and-extend**; it is deliberately not a pure re-embedding of an existing line. `RETURN` adds an arm but does **not close the boundary**. More fluid glyph rendering can be added later while maintaining the same typed underlying graph.

### Invariants and refusals

- Growth retains **all old vertices (injective map), their exact coordinates, and all inherited edges**. This is a conservative v0 rule, not a universal necessity.
- The new graph must remain connected and acyclic.
- Inherited source and resulting target each receive separate canonical SHA-256 digests.
- Different JSON key ordering, edge directions, operation list ordering and source-ref ordering must not affect a receipt.
- No undrawn branch can be recovered from `·` merely because `Y → ·` was a valid quotient.
- No unknown vertex, malformed edge, NaN coordinate, missing source, duplicate ID, or forbidden operator may pass.
- Receipt output is not cryptographic authority or evidence of historical genealogy; semantic assignment belongs to an explicit receiver constitution.

## Reproducible specimen

`specimens/glyph-growth-dot-line-l-u-y-001.json` carries five representations (`DOT`, `STEM`, `ELBOW`, `CUP`, `FORK`) and four declared operations.

```bash
python3 -m unittest discover -s tests -p test_glyph_growth.py -v
python3 skills/3rdi/scripts/compile_glyph_growth.py \
  specimens/glyph-growth-dot-line-l-u-y-001.json --operation point-to-line --check
python3 skills/3rdi/scripts/compile_glyph_growth.py \
  specimens/glyph-growth-dot-line-l-u-y-001.json --operation line-to-elbow --check
python3 skills/3rdi/scripts/compile_glyph_growth.py \
  specimens/glyph-growth-dot-line-l-u-y-001.json --operation elbow-to-cup --check
python3 skills/3rdi/scripts/compile_glyph_growth.py \
  specimens/glyph-growth-dot-line-l-u-y-001.json --operation point-to-fork --check
```

### Cross-module relationship

```text
GlyphTrace  (one shape / multiple formation hypotheses)
    |
    +-- Glyph Transition 001 (different shape / quotient or path deformation)
    |
    +-- Glyph Growth 002 (different shape / declared additive generation)
```

Potential consumers include a visual glyphpad, Toaster compositions, or reLATTE receipt transport. Neither those integrations nor a common protocol is silently enabled in this phase.

**Working law:** *The seed is not the shape it may grow. The visible point is not the memory of the branches that collapsed into it.*
