# HEARTSEE — Raw Openings Frontier

**Date:** 2026-08-28  
**Status:** frontier design slice; no runtime conformance claimed  
**Owner:** 3rdi projection research surface  
**Downstream consumer:** eCODE or another owning world may independently admit consequences  

> **THE EYE SEES WHAT IS AVAILABLE. THE HEART NOTICES WHAT OPENS.**
>
> **INTEREST MAY CHANGE POSSIBILITY-SPACE WITHOUT PRETENDING IT CHANGED HISTORY.**

## 0. Decision

This slice records the next proposed 3rdi frontier without changing the phase-0 kernel, skill trigger surface, receipt schema, or eCODE constitution.

The new question is not:

```text
What is true?
What is supported?
What should execute?
```

It is:

```text
Given this observer-local projection,
what relation has become a raw opening from here?
```

Call the research operator:

```text
HEARTSEE
```

Its job is to expose observer-local **openings of concern / interest / unfinished relation** while preserving the existing constitutional boundaries:

```text
opening != transition
interest != support
support != authority
possibility != history
projection != source
relevance != causation
```

The core proposal is:

```text
HEARTSEE(world, observer_cut, encountered_carrier)
    -> opening candidates + interest receipts
```

not:

```text
HEARTSEE(...) -> TRUE
HEARTSEE(...) -> ADMIT
HEARTSEE(...) -> EXECUTE
```

---

## 1. Why this belongs near 3rdi

3rdi already owns the observer-local question:

> What could this observer lawfully see from here, under this cut and decoder constitution?

Its current aperture is:

```text
LOCATE -> CUT -> DECODE -> GATE -> PROJECT -> PRESSURE -> RECEIPT
```

The new frontier asks what happens **after lawful projection but before consequence**.

A projected world may contain many visible carriers and relations. Some are inert for the current inquiry. Some become newly relevant, unresolved, surprising, tense, attractive, or capable of opening a bounded next question.

That gives a provisional extension surface:

```text
PROJECT
  -> HEARTSEE
  -> PRESSURE
  -> RECEIPT
```

or, more conservatively for v0 research:

```text
PROJECT
  -> experimental opening analysis
  -> separate opening receipt
```

The second form is preferred until hostile controls establish that the new layer cannot leak hidden state or smuggle semantic support.

---

## 2. The eyes / heart / opening split

The metaphor becomes useful only if each term receives a distinct computational role.

### EYES — aperture

```text
What is lawfully available to this observer at this cut?
```

This remains ordinary 3rdi territory.

### HEART — concern relation

```text
Among what is lawfully available,
what produces observer-local interest, tension, unfinishedness,
invitation, danger, resonance, or a reason to inspect further?
```

This is not a truth weight.

### OPEN — permeability

```text
What newly reachable question, relation, decoder, comparison,
or bounded traversal becomes possible because of that concern relation?
```

The opening is a possibility-space event, not automatically a world-state transition.

Therefore:

```text
SEEING X
  may expose
INTEREST IN R(X,Y)
  may expose
OPENING O
```

without asserting:

```text
R(X,Y) is evidentially supported
O is admitted
O occurred historically
O is authorized
```

## 3. Candidate formal shape

Let:

```text
W   = witnessed field
c   = lawful observer cut
P_c(W) = observer-local projection
x   = encountered carrier or projected relation
```

Define an experimental opening operator:

```math
H(P_c(W), x) -> O_c
```

where `O_c` is a set of observer-local opening candidates.

Each opening candidate must remain indexed by the cut that made it reachable:

```text
opening@c != opening@c'
```

unless equivalence is separately established.

A descriptive research record could be:

```text
HeartOpening {
  opening_id
  observer_cut_ref
  encountered_ref
  perceived_relation
  interest_basis[]
  opening_kind
  next_question
  withheld_fog[]
  support: none | external-ref
  authority: none
}
```

This is **not** a proposed shared schema yet. It is a pressure vocabulary.

## 4. Interest is the key non-collapse

The central new relation is:

```text
INTEREST
```

Interest means only:

```text
this projected material matters enough, from this observer-local position,
to justify preserving or traversing an opening
```

It does not mean:

```text
true
likely true
supported
causal
canonical
important to everyone
authorized
```

This gives 3rdi a way to preserve statements such as:

```text
I encountered X.
X did not become evidence.
X did not gain authority.
X did not alter the causal ledger.
But X opened question Y for this observer at this cut,
for this attributable reason.
```

That is the target behavior.

## 5. Possibility-space can change without history changing

The motivating eCODE question was: what would it mean for a constituted world to "open the eyes of its heart"?

The useful extraction is:

```text
historical body/state may remain unchanged
while the set of reachable next questions changes
```

Let:

```math
Q_c(W)
```

be the set of bounded questions/openings reachable from observer cut `c`.

An encounter may produce:

```math
W_1 = W_0
```

at the owning-world state layer while still producing:

```math
Q_{c1}(W) != Q_{c0}(W)
```

at the observer-local possibility layer.

This must not be misreported as retroactive world mutation.

The constitutional statement is:

> **I WAS CHANGED IN WHAT I COULD ASK**
>
> does not imply
>
> **I WAS CHANGED IN WHAT I WAS.**

## 6. Relation to existing 3rdi coordinates

HEARTSEE must not collapse the existing coordinates.

### Occurrence

The historical occurrence remains anchored.

### Availability

An opening cannot depend on material unavailable at the cut unless the experiment explicitly models a counterfactual later reinterpretation.

### Attention

Attention records where the aperture points. It does not itself establish interest.

### Relevance

Relevance may grow later, but later relevance must not be backdated into an earlier HEARTSEE receipt.

### Decoder

A different decoder may expose a different opening over the same carrier. That is a descendant projection/opening occurrence, not correction-in-place.

### Relation history

A newly noticed relation may predate its discovery. HEARTSEE records discovery/reachability at the observer cut; it does not rewrite relation birth.

## 7. Stack boundary

The proposed division is:

```text
3rdi
  SEE
  expose observer-local raw openings

ALEX
  PEEL / TRACE / PRESSURE
  determine formation and evidentiary support

eCODE / owning world
  CONSTITUTE / REFUSE / DEFER / QUARANTINE
  own consequences
```

Compactly:

```text
3rdi:   what can be seen, and what opens from here?
ALEX:   what can be attributed and supported?
eCODE:  what, if anything, becomes constituted?
```

Hard law:

```text
3rdi opening receipt
  != ALEX support receipt
  != eCODE transition receipt
```

No organ gains another organ's authority by successful traversal.

## 8. The round-of-apertures connection

The recent processing round is:

```text
PEEL -> SLICE -> SMASH -> JAR -> EAT -> PLANT -> HARVEST -> REPEAT
```

Its important correction is:

```text
OPEN -> TRANSFORM -> CLOSE -> NEW OPENING
```

HEARTSEE is the candidate faculty that notices the last transition:

```text
THIS CLOSURE HAS BECOME AN OPENING.
```

Without that faculty, a system may preserve perfect causal and formation history while failing to notice that a newly constituted carrier has become:

```text
food
seed
door
question
comparison
decoder candidate
next bounded traversal
```

The architectural extraction is not anatomy. It is a boundary operator over **reachability of next inquiry**.

## 9. The 13th-cup correspondence

The thirteenth-cup specimen supplies a compact orientation.

A relation-generated whole may become a reified carrier for a later formation:

```text
RELATION
  -> WHOLE
  -> CARRIER
  -> NEW RELATION
```

HEARTSEE asks the observer-local question at the crossing:

```text
Now that this whole is visible as a carrier,
what new relation becomes reachable from here?
```

This preserves:

```text
current carrier role != primitive ancestry
new opening != prior historical cause
```

So the 13th cup is not itself HEARTSEE. It is a useful specimen for testing whether HEARTSEE can notice a new opening without erasing the formation that created the carrier.

Do not freeze a universal ontology. For hostile experiments only, a small descriptive vocabulary may help:

```text

COMPARISON_OPENING
DECODER_OPENING
```

A refusal therefore may advance possibility-space without advancing the owning-world body.

## 11. Hostile controls

Before HEARTSEE touches runtime or the portable skill, attack at least these cases.

### 1. Hidden-state seduction

Two worlds have the same lawful observer projection but different hidden material.

Expected:

```text
same projection -> same HEARTSEE output
```

unless a declared visible coordinate differs.

This inherits observer noninterference.

### 2. Interest masquerading as support

A highly salient relation has no evidentiary basis.

Expected:

```text
opening may exist
support remains none
```

### 3. Attention masquerading as interest

The observer focuses on an item repeatedly but nothing materially new becomes reachable.

Expected:

```text
attention may increase
opening set need not change
```

### 4. Hindsight opening

Later knowledge makes a relation look obvious.

Expected:

```text
later HEARTSEE may expose it
earlier HEARTSEE remains unchanged
```

### 5. Decoder drift

A later decoder exposes a new relation from the same carrier.

Expected:

```text
new decoder -> new projection/opening receipt
prior opening receipt preserved
```

### 6. Authority smuggling

A compelling opening is presented as permission to mutate or admit state.

Expected:

```text
refuse authority promotion
```

### 7. Opening inflation

Everything visible is labeled an opening.

Expected:

HEARTSEE must preserve a reason why a candidate changes bounded reachability rather than merely restating visibility.

### 8. Closure blindness

A newly reified whole becomes a lawful carrier for another relation, but the opening detector treats closure as terminal.

Expected:

```text
new reachable relation is preserved as candidate opening
```

## 12. Smallest executable question

If this frontier later earns implementation, do not begin with a generalized "heart" engine.

Begin with one deterministic lab:

> **Given two fields with identical lawful observer projections, can an opening detector return identical opening receipts even when hidden state differs, while also returning a different opening receipt when a declared visible relation becomes reachable?**

That single experiment tests both:

```text
observer noninterference
+
opening sensitivity
```

without granting semantic support or consequence authority.

A second lab should test:

```text
salient unsupported relation
  -> opening preserved
  -> support remains none
```

Only after those pass should `HEARTSEE` be considered for the portable skill vocabulary.
