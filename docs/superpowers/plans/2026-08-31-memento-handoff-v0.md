# 3rdi → MEMENTO Handoff v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Emit one deterministic observer-local 3rdi handoff and ingest it atomically as MEMENTO UNDERSTORY residue without transferring admission, support, canon, or side-effect authority.

**Architecture:** 3rdi owns a pure stdout emitter over an existing `3rdi.projection-receipt/v0`. MEMENTO owns translation, full-batch preflight, and durable UNDERSTORY writes. One canonical fixture is generated by 3rdi and copied byte-for-byte into MEMENTO so contract drift is machine-visible.

**Tech Stack:** Python 3 standard library in 3rdi; Node.js >=20 in MEMENTO; JSON; SHA-256; existing repository canonicalization and validation helpers.

**Spec:** `docs/superpowers/specs/2026-08-31-memento-handoff-v0-design.md`

## Global Constraints

- Preserve `3rdi projection != source != MEMENTO write != MEMENTO admission`.
- 3rdi performs no repository write and never calls MEMENTO.
- MEMENTO validates `[existing UNDERSTORY + entire candidate batch]` before creating any candidate file.
- `emitted_at` is explicit input; no wall clock reads.
- `world_instance_id` is optional and never inferred.
- `residual_fog` may contain structured source identifiers only; never hidden reasoning.
- No ALEX runtime dependency, network access, support/evidence promotion, canon admission, or side-effect authority.
- Keep the existing 2026-08-27 MEMENTO handoff plan as ancestry; this plan refreshes paths and current-owner boundaries against present mains.
